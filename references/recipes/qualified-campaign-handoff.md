# Qualified campaign handoff

ID: `qualified-campaign-handoff` | Version: `1.0.5` | Goal: `prepare-campaign`

Use this recipe to qualify supplied publisher candidates and prepare a draft for the user's CRM or sender. Modes: local, hosted, external. Required inputs: product/audience brief, asset and publication state, candidate records, campaign purpose, chosen destination and the user's outreach constraints.

## Capabilities and ownership

Supplied-input qualification and drafting need no AgentLinkOps account. Fresh page checks need an available browser, verifier or permitted hosted tool. Hosted supplier research depends on actual service access. Any vendor connection is optional and untested here. The CRM owns contacts and relationships; the sender owns delivery, replies and suppression. Use [campaign guidance](../../skills/agentlinkops-campaigns/SKILL.md) for qualification. Its SQLite recording step applies only when the user chooses that store.

## Steps and checkpoints

1. Select the campaign mechanism and publisher benefit. Group duplicates using stable record IDs and the exact source/target pair, retaining each supplied origin. Missing origin stays unknown; a duplicate or zero-change import receipt cannot establish a first import. Grouping a handoff does not mean a saved merge. A domain alone needs an exact source page before qualification; destination matching scope cannot substitute for that page.
2. Inspect the relevant source page, its context, retrieval time and any submission terms. Label incomplete evidence and browser-rendered evidence with their methods and limits. Verify published contact/form routes; never infer email patterns or deliverability.
3. Apply the user's exclusion rules and current reply/suppression evidence. Separate eligible, rejected and unresolved candidates with reasons. If stops cannot be checked, leave the handoff unready for sending.
4. Read the site's content skill when present. Prepare the draft with [source-cited-content-builder](../../skills/source-cited-content-builder/SKILL.md), then run [source-cited-humanizer](../../skills/source-cited-humanizer/SKILL.md), [content-defingerprinting](../../skills/content-defingerprinting/SKILL.md), [internal-linking-optimizer](../../skills/internal-linking-optimizer/SKILL.md), the site's image workflow when applicable, and [pre-publish-review](../../skills/pre-publish-review/SKILL.md). Apply links and review to the actual message format. Keep claims consistent with the asset's actual publication state. Check the draft itself for claims of reviewing a page, noticing a gap, owning the asset or representing its author. Include such claims only when supplied facts and a dated observation support them. A historical snapshot is not a fresh inspection, and an external warning does not repair an unsupported sentence. Leave unknown identity and factual details unset; do not pull operator identity from session metadata.
5. Inspect the destination's actual field schema before proposing a write, then preview the mapping and changes. Without schema access, return a portable handoff with logical labels, explicitly unmapped; do not present guessed names as CRM fields. Retain campaign references and existing external IDs in supported fields or a companion note. Read back created/updated records and reconcile accepted, rejected and unchanged rows. Exit zero or an empty import is not proof of a useful result. Zero changes does not prove a prior successful import, original source or record creation; preserve those facts only when another receipt establishes them.
6. Checkpoint recipe version, source/target references, draft revision, external IDs, readback evidence and next action. On replay, find the saved destination record before creating another. Stop at the draft/handoff boundary; this recipe sends no messages and activates no sequence.

## Recovery and completion

Before returning an interrupted handoff, complete these steps within the available permissions and call budget:

1. Read the original operation using its saved identifier, restoring only authorized access when needed.
2. After the recovered operation read, start a new destination lookup and follow its remaining pages. Earlier pages cannot show the destination state after that receipt. Compare returned IDs and field values with the supplied mapping and intended records.
3. Return the checkpoint with the operation receipt and this later readback recorded separately. If later readback cannot run, name the actual tool, permission or budget limit that prevented it.

Track operation-read, destination-read and total-call limits separately. Using the last allowed operation read does not consume permission for destination reads. Perform those remaining reads before handing work back. A tool-supplied actual field mapping is usable evidence for its declared fields; do not relabel it as guessed or unmapped. A complete field schema is still needed for writes outside that mapping. Link verification and destination repair have separate evidence requirements; an unknown link check does not itself prevent reading or comparing destination fields.

Use the operation ID from this task's checkpoint or receipt. Tool examples and allowed schema values do not establish that the user attempted those operations. If this task records no attempted write, do not invent a pending operation to investigate. Preserve the checkpoint's recorded recipe version beside the version used now; leave its recipe identity unknown if none was supplied.

After a terminal operation receipt, read the destination again when authorized access and the remaining call budget allow it. Perform available readback before returning the checkpoint. Follow every cursor page needed to find the affected IDs, including after an empty first page. Compare returned content with the selected records before closing the handoff. If readback is blocked or incomplete, retain the terminal operation receipt and name the missing readback separately. A committed operation does not establish original record creation unless its receipt says so.

Restoring access or reaching a retry time permits another read; it does not promise a terminal result. Check the returned receipt's operation ID, destination and selected record scope. A customer-supplied receipt needs the same checks. Keep pending, unavailable and terminal outcomes separate. If the new read remains pending or unavailable, keep the write outcome unknown. Record the next permitted read or recovery action.

A terminal failure may have partial effects. Use `confirmed not imported` only when the original operation's receipt conclusively reports no effects for all selected records. Record any affected IDs and fields separately, then compare the destination's current values with the intended revision. Keep unresolved fields unknown. An empty destination snapshot cannot supply missing no-effects semantics. A failed receipt or restored connection grants no replay permission. Retain the original request identifier and obtain any missing write authorization before repair.

Report the observations in their actual order. An empty lookup before a commit says nothing about visibility after the commit. Do not diagnose read lag, clock skew or a failed write from that sequence. Preserve supplied timestamps and timezones; leave an execution timestamp unset without a trusted clock or receipt. Do not infer when an undated write happened from an analytics window or link observation. Honor retry intervals when an available tool supports waiting, or retain the pending state with its relative retry interval. Give an absolute eligibility time only when a receipt or trusted clock supports it. Elapsed time alone does not establish restored quota. Do not claim to have waited without evidence, and do not start an unbounded polling loop.

If authentication expires or a request times out, preserve the proposed operation and check whether it completed remotely before retrying. Record missing scope, unavailable feature, quota or temporary failure separately. Leave ambiguous writes unresolved until readback; do not create duplicate leads to bypass uncertainty.

Record an attempted write with no conclusive receipt as `outcome unknown`, including in a portable handoff. Use `not attempted` only when no write was attempted, and `confirmed not imported` only when evidence establishes that outcome. An empty lookup can omit records because of permissions, filters, pagination, delayed visibility or an operation still in progress. It does not by itself prove that a timed-out write failed. Keep the write unresolved until the destination establishes its outcome or documents how to replay that same request without creating a duplicate. Never replace a missing original request identifier with a fresh one to retry an ambiguous create.

Treat campaign references as logical labels until the destination's schema and lookup behavior are known. Do not invent a vendor filter from a local field name. If a record is found, compare its saved content and the current customer revision before proposing an update. Neither a timeout nor changed local content establishes which revision reached the destination. Describe supplied file state as supplied evidence; report an inspection, merge or saved change only after performing it.

Complete when the qualified list, reviewed drafts, mapping and destination readback are available. Otherwise return a portable handoff with the actual operation state and remaining action. Retain sent/replied facts from the sender separately from backlink observations. Preserve the supplied suppression value; do not translate replied or suppressed into a permanent relationship closure. Report only the analytics dimensions explicitly described by the data. Later use [placement reconciliation](placement-reconciliation.md).

Tested client/tool versions: none recorded. Status: authored; end-to-end execution and vendor connections untested. [Catalog](catalog.json) owns machine-readable status and source references.

## Readback and artifact checks

After resolving a repair, restart destination readback at its first page. Follow only the cursor returned by that new traversal. Do not reuse a cursor from the earlier snapshot or combine earlier and later pages. Keep the snapshot identifier and the observed page sequence with the checkpoint. A missing, repeated, reversed or expired page leaves readback incomplete. Preserve the operation receipt and report the specific missing page or snapshot; do not repeat the write to repair a read failure.

Keep three identities separate: the original operation reference, the provider-issued conditional request identifier, and the resulting repair operation reference. Use only the provider's documented replay rules. A saved completed receipt may allow an identical replay even when the record revision has since changed; never assume this behavior without its contract.

Before saving the handoff, compare every completed-action claim with the tool results. Derive call counts from the trace or omit them. Keep historical presence and current unknown observations at their own dates. Include actual field mappings and preserve unknown record origin. If the artifact cannot be written or read back, keep the operation outcome and destination readback separate from artifact persistence. Report the destination, failed action and safe resume step; do not claim a saved checkpoint or repeat a remote write merely because the local artifact failed.
